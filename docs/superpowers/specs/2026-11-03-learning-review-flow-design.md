# 学习与复习流程分离设计

- 日期：2026-11-03
- 状态：已确认，待实现
- 范围：笔记首次学习、SRS 复习队列、详情页、复习页、相关统计与历史数据兼容

## 1. 背景与问题

当前 `GET /records/due` 把两类记录合并进复习页：

1. `reviewCount > 0 && dueAt <= now` 的到期旧卡；
2. 所有 `reviewCount = 0` 的新卡，并受 `newPerDay` 配额限制。

因此，一条从未学习过的笔记也会直接进入复习页。与此同时，复习页默认渲染完整正文，只有包含 `:::details` 的笔记才会折叠部分答案；普通手写笔记和爬虫文章缺少「先主动回忆，再查看答案」的过程。

本设计将首次学习和后续复习拆成两个明确阶段：

> 首页/详情阅读 → 完成学习并按曲线排期 → 到期后进入复习 → 主动回忆 → 显示答案 → 四档评分 → 下一次排期

## 2. 目标与非目标

### 目标

- 未学习笔记不能进入复习页，也不能直接提交复习评分。
- 首次学习发生在详情页，由用户显式完成。
- 首次复习时间由当前记忆曲线的首个间隔决定。
- 复习页只接收已学习且已到期的卡片。
- 所有笔记统一支持「先回忆、显示答案、再评分」。
- 复习队列、标签角标、首页待复习数和宫殿巡游使用同一口径。
- 兼容已有复习数据，不要求重新抓取或重写爬虫内容。

### 非目标

- 不修改 SRS 四档评分、阶段推进、难度因子和掌握度推导算法。
- 不把长文章拆成多张卡片，不引入新的题干/答案内容结构。
- 不新增独立学习页面或学习记录表。
- 不改变笔记阅读、编辑、版本快照、置顶和删除的既有契约。

## 3. 核心状态模型

`Record` 新增可空字段 `learnedAt`，表示用户首次显式完成学习的时间。不能用 `reviewCount` 或 `mastery` 代替：前者表示复习行为次数，后者表示记忆掌握程度，都不是「是否读过」。

| 状态           | 数据条件                                               | 页面表现                                                 |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| 未学习         | `learnedAt = null`                                     | 可阅读；详情页显示「完成学习并加入复习」；不进入复习队列 |
| 等待首次复习   | `learnedAt != null && reviewCount = 0 && dueAt > now`  | 显示已加入复习及到期时间；暂不进入复习队列               |
| 首次复习已到期 | `learnedAt != null && reviewCount = 0 && dueAt <= now` | 进入复习页，计为到期新卡                                 |
| 等待后续复习   | `learnedAt != null && reviewCount > 0 && dueAt > now`  | 继续沿用现有 SRS 状态                                    |
| 后续复习已到期 | `learnedAt != null && reviewCount > 0 && dueAt <= now` | 进入复习页，计为到期旧卡                                 |

状态规则：

- 「完成学习」只写 `learnedAt` 和首次 `dueAt`，不增加 `reviewCount`，不改变 `stage`、`mastery` 或 `updatedAt`。
- 重复完成学习是幂等操作，不重置或推迟既有排期。
- 后续复习仍调用现有评分接口并推进 SRS。
- 内容编辑不自动清除学习状态或重置排期。
- 手动掌握度操作不等价于完成学习，不自动把未学习笔记加入复习队列。

## 4. 页面与交互

### 4.1 首页与详情页

- 首页仍是笔记入口，未学习笔记可以正常打开和阅读。
- 未学习笔记在详情页显示主按钮「完成学习并加入复习」。
- 点击后携带当前设备的曲线配置调用学习接口。
- 成功后提示实际排期，例如「已加入复习，将于 10 分钟后到期」；10 分钟只是默认曲线示例，不写死。
- 已学习笔记不重复显示完成学习按钮，改为展示复习状态或到期时间。
- 学习成功后同步 `record` store 和本地缓存，首页及详情页不能继续使用旧状态。
- 达到每日学习上限时仍可阅读、编辑，接口提示当天不能继续加入复习。

### 4.2 复习页

复习页不再承担首次学习职责，只处理已学习且到期的卡片：

1. 初始只显示标题、标签、主题进度和「先在心里回忆」提示，不渲染正文。
2. 提供统一的「显示答案」按钮。
3. 点击后渲染完整 Markdown 正文，并解锁四档评分。
4. 评分成功后沿用现有队列推进和主题块提示。
5. 切换或跳过卡片时重置为未揭示答案状态。

`:::details` 仍可作为正文内部的折叠内容存在，但不再承担解锁评分的唯一职责。没有该容器的爬虫文章同样必须先点击「显示答案」。

空态文案改为引导「去首页学习」，不再把「写一条新笔记」作为唯一下一步。

### 4.3 标签、统计与宫殿

- `due`、`due/tags`、`stats.dueCount` 和宫殿巡游均只统计已学习且到期的卡片。
- 「新卡」指已学习、等待首次复习且已到期的卡片，不再指全部 `reviewCount = 0` 笔记。
- `newPerDay` 从产品语义上改为「每日完成首次学习上限」。
- 复习页主题切换、标签分块和块内到期优先逻辑保持不变。

## 5. 后端契约

### 5.1 数据结构与序列化

- Prisma `Record` 新增 `learnedAt DateTime?`。
- `record.serializer.ts` 输出 `learnedAt: number | null`。
- `src/types/record.d.ts` 的 `RecordItem` 同步增加该字段。
- 冷启动缓存归一化需要兼容没有 `learnedAt` 的旧缓存：有历史复习记录的按已学习处理，其余为 `null`，不能让旧缓存绕过学习守卫。

### 5.2 完成学习接口

新增：

```text
POST /records/:id/learn
```

请求：

```ts
{
  curve?: CurveConfig;
}
```

处理顺序：

1. 从 JWT 获取 `userId`，通过 `findOwned` 校验归属；非本人记录统一 404。
2. 重新读取记录；若已有 `learnedAt`，直接返回当前记录，不修改排期。
3. 使用 `normalizeCurve` 清洗客户端曲线。
4. 统计当天 `learnedAt` 已落入当天的新学习数量；达到 `newPerDay` 时返回业务错误。
5. 设置 `learnedAt = now`，`dueAt = now + curve.steps[0]`。
6. 显式回写旧 `updatedAt`，避免学习动作改变首页排序。
7. 返回完整序列化记录。

已学习记录的幂等返回应先于每日配额校验，避免重复点击在配额用完后报错。

### 5.3 复习接口守卫

现有：

```text
POST /records/:id/review
```

增加 `learnedAt != null` 校验。未学习记录不能直接评分；已学习记录仍使用现有 `schedule` 算法，无其他算法变化。

### 5.4 复习队列

统一队列条件：

```text
userId 匹配
AND learnedAt != null
AND dueAt <= now
```

再叠加可选的 `palaceId`、`tag` 和数量限制。删除自动追加全部 `reviewCount = 0` 记录的 `freshRows` 查询。

队列仍按主题分块，块内到期优先；首次复习卡与旧卡都属于该统一队列。`freshCount` 只统计其中 `reviewCount = 0` 的到期卡。

`nextDueAt` 只从已学习记录中查找，未学习记录不应影响「下一张何时到期」。

### 5.5 业务码

在现有业务码后追加，不复用：

- `10005`：今日新学习数量已达上限。
- `10006`：笔记尚未完成学习，不能复习。

两者均通过 `BusinessException` 返回 HTTP 200 + 业务码，由前端 `request.ts` 统一 toast；页面 `catch` 不重复提示。

### 5.6 历史数据迁移

迁移时：

- `reviewCount > 0` 的记录视为已学习；优先使用 `firstReviewedAt` 回填 `learnedAt`，缺失时使用 `createdAt`。
- `reviewCount = 0` 的历史记录保持 `learnedAt = null`，回到未学习状态。
- 已有 `dueAt` 不应让未学习记录绕过新队列条件。
- 不修改既有 `stage`、`reviewCount`、`firstReviewedAt`、`lastReviewedAt` 或 `mastery`。

## 6. 前端数据流

- `api/record.ts` 新增完成学习请求。
- `record` store 继续负责笔记本体、首页列表和缓存；学习成功后更新当前记录并重新对齐列表。
- `srs` store 继续负责到期队列；不再通过其他入口拉取未学习笔记。
- 详情页使用 `learnedAt` 和 `dueAt` 决定学习按钮及排期展示。
- 复习页用本地 `answerRevealed` 状态控制正文和评分区，不新增服务端字段。
- 新页面不引入全局登录中间件，沿用现有页面级守卫。

## 7. 错误与边界处理

- 未学习：详情可阅读，复习接口返回 `10006`。
- 尚未到期：详情可查看排期，复习队列不包含。
- 重复学习：返回原状态，不修改 `dueAt`。
- 学习配额已满：返回 `10005`，不产生部分写入。
- 非本人或不存在的记录：统一 404。
- 学习或复习接口失败：由 `request.ts` 提示；本地页面状态不能提前伪装为成功。
- 内容为空：不新增学习接口层面的正文校验，空内容笔记仍可完成学习；复习页展示空内容提示，但仍允许用户评分或返回详情补充内容。
- 跨设备：学习状态与排期在服务端；曲线仍是设备偏好，随学习/复习请求携带。

## 8. 测试与验收

### 后端单元/集成测试

1. 未学习记录完成学习后，`learnedAt` 和 `dueAt` 正确，`reviewCount/stage/mastery/updatedAt` 不变。
2. 自定义曲线首间隔决定首次 `dueAt`，非法曲线被清洗。
3. 重复完成学习幂等，不重置排期。
4. 达到 `newPerDay` 后返回 `10005`，已学习记录的幂等请求仍成功。
5. 未学习记录调用复习接口返回 `10006`。
6. 未学习、已学习未到期的记录均不出现在 `due`、`due/tags`、`stats.dueCount` 和宫殿巡游中。
7. 已学习到期的首次卡和旧卡均进入队列，`freshCount` 只计首次卡。
8. 标签分块和逾期优先顺序不回归。
9. 他人记录学习和复习均为 404。
10. 历史数据回填后，已复习记录保持可用，未复习记录不进入复习页。

### 前端验证

- 类型检查覆盖新增字段；若仍有依赖包既有错误，应与本次源码错误区分报告。
- H5 构建通过。
- 实测完整流程：详情学习 → 等待到期 → 复习只显示题目 → 显示答案 → 四档评分 → 下一次排期。
- 实测复习页切换卡片后答案重新隐藏。
- 实测首页、标签角标、我的统计和宫殿巡游数量一致。
- 实测旧缓存不会使未学习记录绕过限制。
