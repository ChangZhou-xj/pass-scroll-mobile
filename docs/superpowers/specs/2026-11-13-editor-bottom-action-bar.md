# 编辑页操作重设计：底部固定操作栏

- 日期：2026-11-13
- 问题：编辑页的「保存」在导航右上角、「返回」在左上角。写长文时人在页面底部，保存/退出都要拉回最上面；页内/浮动两条「编辑|预览」切换条都不能代替这两个动作。

## 方案对比

| 方案                             | 结论                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| A. 底部固定操作栏（返回 + 保存） | ✅ 采用：拇指热区、任何滚动位置一键可达，两态（编辑/预览）通用  |
| B. 内容底部内联按钮              | ❌ 依然要滚到内容末尾，长文不解决                               |
| C. 右下角浮动保存钮              | ❌ 只解决保存，返回仍需回顶部；且与右上浮动切换条形成两个浮动件 |

## 设计

1. **职责划分**：顶部导航只做「返回 + 标题」（标准习惯保留）；右上角「保存」按钮移除；底部新增固定操作栏 = 左「返回」(secondary) + 右「保存」(primary)。
2. **键盘避让（v2 修正）**：初版采用「focus 隐藏底栏」，实践证明是错误方案——键盘开着或焦点未释放时底栏整体消失，保存/返回无入口，移动端滚动不触发 blur 会一直挂起。改为成熟方案（微信聊天输入栏同款）：**底栏常驻 + 骑在键盘上方**——
   - MP/App：输入框默认 `adjust-position` 把页面连同 fixed 底栏整体推到键盘上方，零代码；
   - H5 Android：键盘收缩 layout viewport，fixed 底栏自动上移；
   - H5 iOS：键盘不收缩视口，用 `visualViewport` 的「layout 视口 − visual 视口」差算出键盘高度，底栏 `translateY(-kbHeight)` 抬起（`#ifdef H5` 内实现，监听 resize，onUnmounted 清理；仅输入框聚焦期间生效，避免滚动误抬）。
3. **内容避让**：页面容器 padding-bottom = `calc(200rpx + env(safe-area-inset-bottom))`（栏高 96rpx + 上下内衬 32rpx + 余量）。颜色/边框样式对齐 CustomTabBar（白底 + 顶部 hairline）。
4. **返回逻辑**：与 `CustomNavBar.goBack` 一致（栈 > 1 → navigateBack；否则 reLaunch 回首页兜底）。底栏返回不随 saving 禁用。
5. **保存逻辑不变**：仍走 `handleSave`（乐观锁冲突兜底等原有行为全部保留）。

## 为什么不写单测

本次改动是布局与事件绑定，无新增纯函数/状态机；可测逻辑（`handleSave`、`goBack`）是既有代码的搬运，验证靠 `vue-tsc` + `eslint` + 构建 + 真机手测（键盘弹出/收起、safe-area、预览态底栏）。
